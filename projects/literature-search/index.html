Semantic and Personalized Search
for KTH's Scientific Literature

Georges Tohme, Annysia Dupaya, Gustaw Siedlarski, Roger Vendrell Colet
A project we built as students [2025] at KTH Royal Institute of Technology.
Report Code

This project builds a search engine for KTH's Computer Science literature that goes beyond exact keyword matches: dense sentence embeddings retrieve papers by meaning, and a learning-to-rank model then reranks them using a profile of the querying author's own research interests and their position in this coauthorship graph.

Abstract

Search portals for scientific literature typically rely on exact keyword matches, which struggle whenever a query's wording doesn't happen to line up with a paper's. We build a search engine over the Computer Science subset of KTH's DiVA publication archive that replaces keyword matching with dense sentence embeddings and k-nearest-neighbor retrieval, then layer a personalization step on top: a learning-to-rank model reranks the semantic results using a profile of the querying author's inferred research interests, built from their past publications and their position in a coauthorship graph. Comparing all three retrieval modes, lexical, semantic, and personalized, on a set of manually judged queries, we find that semantic and personalized search generally outperform exact keyword matching, though which of the two wins out depends on how specific or ambiguous the query is.

The Problem: Exact Keyword Matches Aren't Enough

Portals like KTH's DiVA archive traditionally search scientific literature the same way a plain text search engine would: by matching the words in a query against the words in a paper's title, authors, and abstract. That works well when a query happens to use the same vocabulary as the paper, but scientific writing is full of synonyms, jargon, and near-misses, a query for "pickup and delivery" won't match a paper that only ever says "vehicle routing", even though the two are closely related. As the volume of published literature keeps growing, that mismatch becomes a bigger obstacle to finding the right paper.

There's a second source of signal exact keyword search leaves on the table entirely: many users searching a database like DiVA are themselves published authors. A user's own publication history, and their place in the web of collaborations around them, says a lot about what kind of paper they're actually looking for, the same way a shopping site uses your past purchases to steer your search results. This project explores both ideas: replacing keyword matching with a semantic understanding of a query, and using an author's own research profile to personalize what a semantic search surfaces.

Method

We build three retrieval modes on top of the same Elasticsearch index, standard keyword search as a baseline, semantic search, and personalized search, and compare all three:

  1. Collect the Computer Science subset of KTH's publications from the DiVA archive, and index each paper's title, authors, and abstract in Elasticsearch for lexical (keyword) search.
  2. Encode every abstract with a pretrained sentence-transformer model and store the resulting vectors as a dense_vector field, enabling k-nearest-neighbor semantic search.
  3. Assign each paper a distribution over research topics with zero-shot classification, and average an author's topic distributions across their past papers into a personal research-interest profile.
  4. Build a coauthorship graph connecting authors who have published together, as a proxy for how closely related two authors' interests are likely to be.
  5. Simulate real user interactions by generating synthetic search queries from each author's own keywords, scored by the coauthorship distance between the querying author and each paper's authors.
  6. Train a learning-to-rank model on these synthetic judgments to rerank a semantic search's results according to the querying author's profile.
  7. Evaluate lexical, semantic, and personalized search against each other on a set of manually judged queries, using NDCG@50.

From Lexical to Personalized Search

Each retrieval mode builds directly on the one before it: the personalized search reranks the semantic search's results, which in turn is compared against the plain lexical baseline.

Standard and Semantic Search

The lexical baseline is a standard Elasticsearch query over each paper's title, authors, and abstract, the kind of search a keyword-matching system would already provide. The semantic option instead applies a general-purpose sentence-transformer model (all-mpnet-base-v2) to every paper's abstract at indexing time, storing the resulting vector as a dense_vector field. At query time, the same model embeds the search query, and a k-nearest-neighbor search over the indexed vectors, using an L2-norm similarity, retrieves and ranks the most semantically related papers. Using sentence-transformer embeddings for literature search this way is a relatively recent idea, with encouraging results already reported in the medical-literature domain[1][6].

Topic Assignment

To build a usable research-interest profile for each author, we first need a compact representation of what each paper is about. We use a zero-shot classification model (facebook/bart-large-mnli[4]) to score every paper against about twenty predefined topic categories, such as "Machine Learning / Deep Learning", "Computer Vision / 3D", or "Natural Language Processing", by encoding the paper's title, abstract, and keywords together with each candidate topic and comparing them in the model's embedding space. This needs no labeled training data, since we can already use the pretrained model.

Averaging these topic-probability vectors across every paper an author has published gives us a single vector summarizing that author's research interests, which we store as their profile.

Coauthorship Graph

Alongside topical interests, we model collaboration directly: a graph where each node is an author and each edge connects two authors who have coauthored a paper together. Academic collaboration networks are known to exhibit high clustering and small-world structure[7], meaning authors tend to cluster into communities defined by shared topics of interest, so two authors close together in this graph are a reasonable proxy for two authors with related research interests. In the reranking step, we consider not just an author's direct coauthors but also collaborators up to three degrees of separation away.

Query Generation

Training a reranking model needs example (query, result, relevance) judgments, and we have no real search logs to draw them from. Instead, we simulate user behavior: for every keyword attached to an author's papers, we generate a synthetic query from that author, and score every paper in the dataset against it by the coauthorship distance between the querying author and the paper's authors, from 3 (the two have worked together directly) down to 0 (no connection at all). This mirrors the way session or shopping-cart data is used to train two-tower ranking models in industrial settings[2][3], substituting collaboration distance for the click or purchase signal we don't have.

Model Training

Following the approach described by Jakob[5] for learning-to-rank with Elasticsearch, we train an XGBoost ranking model (XGBRanker) on the synthetic judgments above. Each document is featurized with its lexical relevance to the query (BM25 scores over content and title), a one-hot encoding of its dominant topic, and the querying author's preference score for each topic.

Once trained, the model can rescore any semantic search's results at query time: we look up the querying author's topic-preference profile and feed it, along with the candidate documents, to the model to produce the final personalized ranking.

Evaluation & Results

We evaluate all three retrieval modes with NDCG@50 (normalized discounted cumulative gain), which rewards relevant results for appearing early in a ranked list:

$$ NDCG@K = \frac{DCG@K}{IDCG@K}, \qquad DCG@K = \sum_{i=1}^{K} \frac{rel_i}{\log_2(i+1)} $$

where $rel_i$ is the relevance of the result at rank $i$ (0-3) and $IDCG@K$ is the same sum under the ideal ranking, so $NDCG@K = 1$ exactly when the results are sorted perfectly.

To avoid biasing our own judgments, we picked a handful of authors with enough publications to infer their research interests, built a search query from each one's topics, and pooled the top 50 results returned by each of the three retrieval modes, shuffled together so we couldn't tell which method produced which result. Each pooled result was then manually rated 0-3 for relevance before computing NDCG@50 per method.

Lexical search wins only on "sensor integration techniques", a query whose wording happens to match niche paper keywords almost exactly. Everywhere else it trails both semantic and personalized search by a wide margin. Between the two, personalized search tends to win on vague, broad queries ("pickup and delivery", "modeling new environments"), where reranking by the author's known interests helps disambiguate what they actually mean, while on queries that are already specific ("integrating CNNs with robotics systems"), plain semantic search does better: the query alone is informative enough that folding in the author's general profile mostly adds noise.

Discussion

Both semantic and personalized search clearly outperform exact keyword matching on this dataset, and the pattern in where personalization helps, and where it doesn't, makes intuitive sense: an author profile is most useful exactly when the query itself is underspecified.

The biggest caveat is how synthetic our evaluation is on both ends. The relevance judgments used to train the reranker come from coauthorship distance standing in for real user feedback, not from anyone actually searching and clicking; and the results were scored on a small, manually judged set of queries rather than a large benchmark. Both choices were necessary given the lack of real search logs for this dataset, but they mean the NDCG numbers above should be read as suggestive rather than statistically rigorous. The natural next step would be collecting real user interactions, even a small pilot, to train and evaluate the reranker against.

The dataset itself is also narrow by design: only the Computer Science subset of KTH-affiliated publications in DiVA. Extending it to more departments, or to a larger literature database, would test whether the coauthor-graph and topic-profile approach to personalization still holds up at a scale closer to a real research-search product.
